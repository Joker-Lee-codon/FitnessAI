- (direction) 旧 PRD 或 UX 措辞冲突时，以 2026-09-10 最终 Architecture Spine 作为最新 Product Owner 权威；不重开已确认的产品或架构选择。
- (direction) 生成英文规范实施 SPEC 及结构一致的 zh-CN 副本，供 vibe coding 与人工核验使用。
- (decision) SPEC 覆盖可供个人使用的核心产品私有 Alpha；public-beta 云连续性与 Post-Alpha 扩展保持 Gate 后续范围。
- (decision) 契约采用精简 kernel 加 adopted PRD、UX、architecture、native UI、design-system companions，以及 spec-authored implementation/verification companions。
- (decision) PRD 与 UX 已于 2026-09-10 上游对齐一等纯手机记录，以及对所选本地 Apple Health 摘要的逐请求一次性远程使用。
- (capability) CAP-1：训练者可通过文字 AI 创建或修改完整结构化 Training Plan，审核全部字段或 Diff，并且只有在 digest 绑定的明确批准后激活一个不可变 revision；成功标准为每次有效批准产生一个完整 revision，静默或部分激活为零。
- (capability) CAP-2：训练者可在 Apple Watch 执行已传递 Plan 快照或自由训练，事实本地保存且离线可用；成功标准为 complete 或明确 incomplete 场次在断连与恢复后让每项已提交事实恰好出现一次。
- (capability) CAP-3：无 Watch 训练者可在 iPhone 使用相同身份、状态、纠错与 Analysis 进行计划或自由训练；成功标准为事实与恢复语义一致，不模拟 Watch 自动能力或建立第二领域模型。
- (capability) CAP-4：受支持 Watch 配置可通过置信度、abstention、快速纠正与手动 fallback 辅助 Exercise 分类、组边界与次数；成功标准为分别通过冻结 PRD Gate，且不支持路径不声称成功。
- (capability) CAP-5：Opt-in 用户可验证、纠正并明确开启高置信 RPE auto-use，同时保留 provenance 与 drift recovery；成功标准为各类 RPE 状态分离且无递归标签。
- (capability) CAP-6：Watch 只在冻结双信号窗口后提供忘记 Finish 提示且永不自动结束；成功标准为手动权威、缺失信号抑制与 cooldown 均通过真机测试。
- (capability) CAP-7：用户可纠正、split、merge、insert、delete、恢复、传输和解决冲突事实，无静默覆盖或重复；成功标准为仅追加因果 revision 保全全部用户事实直至安全生效值出现。
- (capability) CAP-8：用户可查看 History 及仅从生效 Actual Sets 派生的周/月/所选 Exercise Analysis；成功标准为结果真实标记 current、stale、pending、partial 或 excluded，无虚假精确。
- (capability) CAP-9：用户可授权最小权限 Apple Health、保持 FitnessAI 本地权威，并为所选本地摘要单独预览远程授权；成功标准为状态可观察且 Gate 前远程 Health 流量为零。
- (capability) CAP-10：用户可导出一个有界 FitnessAI JSON Plan，并只能在完整预览后导入为独立草稿；成功标准为无隐藏数据、parser abuse、静默遗漏、merge、overwrite 或 activation。
- (capability) CAP-11：完成场次可显示一次 Review、Later 或 Disable 邀请并进入既有授权/提案流程；成功标准为仅显示或关闭不发送数据，也不创建 authorization、proposal、approval 或 mutation。
- (capability) CAP-12：每个 Alpha 页面实现已接受原生导航、Titanium Measure 语义、恢复状态与无障碍合同；成功标准为全部必需 light/dark、Dynamic Type、VoiceOver、error、empty、loading、offline、recovery 行为且无占位页。
- (capability) CAP-13：用户可查看规范 Exercise 支持、映射、身体部位/运动属性与简明合规教学；成功标准为 supported、limited、manual-only 状态明确，无未授权媒体或单腕全身判断。
- (constraint) 使用一个本地优先六边形模块化单体仓库/workspace、独立 iPhone/Watch targets 与本地 Swift Package；domain 不依赖 UI、存储、设备、Health、sensor 或 AI provider framework。
- (constraint) 使用 Xcode 26.6、Swift 6.3.3、原生 SwiftUI、轻量 MVVM、显式状态机，以及通过精确锁定 GRDB 7.11.1 使用的系统 SQLite。
- (constraint) 每次用户或批准 AI 修改是带稳定 ID 的仅追加 revision，与持久 outbox/invalidations 原子提交；UI 成功晚于 commit，设备时间永不决定事实。
- (constraint) iPhone 拥有 Plans、长期记录、完整冲突解决、Analysis、AI、Health 与 exchange；被选记录设备拥有 live session，且不可变 Plan snapshot 在 Start 后不变。
- (constraint) 重要 iPhone-Watch 传输有确认且具因果；只有兼容 whole-object applied 才允许激活或清理，重试幂等。
- (constraint) AI、HealthKit、Watch 传递、网络或可选自动能力失败时手动本地记录继续；不支持或不确定路径 fail closed 到 manual/pending。
- (constraint) Alpha Watch 自动证据从 Series 11 46 mm、左腕、表冠在屏幕右侧、右手惯用与架构列出的八个 v1 候选 Exercise 开始；更广支持需独立真机证据。
- (constraint) Exercise、rep、load 与 RPE prompt 在约 20 组代表场次共享最多五次主动预算；只在安全休息提示。
- (constraint) 忘记 Finish 需要恢复与无力量活动同时持续 15 分钟，信号缺失时抑制，永不自动结束，Continue 后冷却 15 分钟。
- (constraint) 内置 Alpha AI 是 gateway 后的 DeepSeek；BYOK 仅 DeepSeek，key 仅本机 Keychain 且直连；排除任意 provider URL。
- (constraint) 每次远程请求消费一次 authorization，绑定 route/provider/account、purpose、categories/window、outbound digest、policy version 与 expiry；HealthKit permission 与 proposal approval 不能替代。
- (constraint) FitnessAI 本地记录对 HealthKit 保持权威；远程 Health 仅限所选本地摘要，服务商/法律/隐私/区域/保留/训练用途/删除/撤回/用户权利 Gate 前禁用真实传输。
- (constraint) Plan exchange 是一个普通未压缩 UTF-8 JSON Plan，遵守 AD-10 体积、深度、数量、备注、映射、metadata 与 draft-only 限制；禁止 executable、external reference、attachment、partial import、merge、activation、overwrite。
- (constraint) Stores、sidecars、outbox 与 chunks 使用 completeUntilFirstUserAuthentication 并排除 iCloud/普通备份；secrets 使用仅本机非同步 Keychain；不可读 store 永不替换为空。
- (constraint) Titanium Measure semantic tokens 与原生平台行为是展示权威；iPhone 顶层为 Plan、History、Analysis、More 且 Plan 为 root；Watch 浅层且任务专用。
- (constraint) 发布证据包含 compile/domain/schema/safety/persistence/sync/AI-contract/secret/migration/fault/accessibility/paired-device/真机检查；私有 Alpha telemetry 默认关闭。
- (constraint) 体积 Gate：iPhone thinned installed ≤500 MB；Watch uncompressed <75 MB、installed target ≤25 MB；Watch ML ≤6 MB；RPE ≤2 MB。
- (decision) 首个 coding 顺序为 contract/persistence foundations、手动 iPhone session、配对 Watch transfer/manual capture、AI proposal lifecycle、History/Analysis，最后是证据门控自动能力与外部 adapters；每个 slice 都可纵向演示。
- (assumption) 缺失的 project-context.md 不含其他绑定决定，因为仓库 AGENTS.md 与指定 planning artifacts 均可用且已完整读取。
- (question) 第一条 AI Plan Story 前，Product Owner 将冻结哪些 Safety Rule Pack v1 units、contradictions、Exercise support、volume、intensity 与 load progression 数字边界和 golden fixtures？
- (question) 内置 DeepSeek 流量前，将批准哪些法律主体、runtime provider、processing region、subprocessors、retention/cache、training use、deletion/revocation、disclosure、endpoint、ceilings、rollback owner 与 kill switch 记录？
- (question) 真实 Apple Health 摘要流量前，哪份 Apple health/fitness purpose、DeepSeek processor/contract、privacy、cross-border、retention、deletion、revocation 与 user-rights 书面审核将关闭 Gate？
- (question) 自动能力验收前，将预注册哪些冻结 datasets、denominators、slices、confidence thresholds、RPE baseline improvement/burden limits 与 false/missed reminder thresholds，并禁止揭盲后放宽？
- (question) Plan import 验收前，哪些 parser time 与 memory budget 将补充已冻结 AD-10 结构限制？
- (note) 从契约丢弃的 wrapper-only 内容：工作流仪式、历史 review prose、除 non-goal 外的 vivo 淘汰实现细节，以及不改变实施决定的展示 fixture 值。
- (capability) CAP-14：用户可接受、编辑或拒绝下一组负重建议与规范 substitute Exercises，同时 planned/Actual 事实分离；成功标准为无用户动作不产生修改，未来 Plan 变化进入完整 Diff 批准。
- (event) 自检 Pass 1 coherence verdict：PASS；14 个稳定 capability 均有 intent 与可测 success，constraints 会改变设计，non-goals 与具体 success signal 存在，开放缺口明确。
- (event) 自检 Pass 2 preservation verdict：补充 CAP-14 及显式 native UI/design-system companions 后 PASS；全部承重产品、UX、架构、实施、安全、隐私、失败、证据与验证声明均进入 kernel 或必读 companion。
- (event) FitnessAI 实施 SPEC 于 2026-09-10 定稿，双语 artifact 一致，上游 PRD/UX 对齐完成。
