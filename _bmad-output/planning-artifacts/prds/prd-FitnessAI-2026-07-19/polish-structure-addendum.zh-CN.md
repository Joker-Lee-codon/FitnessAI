# 结构审阅 — FitnessAI PRD 补充材料

## 文档摘要

- **目的：**保留支持链顶层 PRD 的证据、理由、被否决方案及与架构相关的机制，同时避免成为第二份规范性规格。
- **受众：**架构、UX、合规及下游工作流读者。
- **读者类型：**人类；保留有助于跨职能审阅的证据、来源链接、解释性铺垫和简短总结。
- **核心问题：**下游读者在应用权威 PRD 时，必须理解哪些证据、被否决方案和实现边界？
- **目的陈述：**本文档旨在帮助架构、UX、合规及下游工作流读者理解 PRD 边界背后的证据与理由，并作出一致的下游决策。
- **结构模型：**战略/上下文（Pyramid），并按关注点分组以便人类随机访问。
- **风格指南：**项目 `AGENTS.md` 的中英文同步约定和 `bmad-prd` 的 addendum 角色覆盖通用精简原则；PRD 仍是规范性权威来源，addendum 保留证据、理由、被否决方案、机制和技术尽职调查。
- **当前长度：**英文版共 1,437 个英文单词，标题下有 11 个章节（7 个主要章节和 4 个子章节）。同步中文版在相同 11 个章节中约有 2,619 个可计数单位（汉字加拉丁字母/数字 token）。

## 信息流分析

当前顺序对实现导向的读者而言可读，但与可能的跨职能阅读路径并不匹配。最高风险的安全与授权边界出现在平台设置之后，相关架构关注点和模型证据关注点也未成组排列。内容铺垫充分、视觉节奏适当，但密集的 RPE 章节缺少用于区分证据限制、部署机制、交互信任 Gate 和科学发布验证的子标题。直接来源链接和 PRD 需求引用是有效的理解辅助，应予保留。

## 建议

### 1. MOVE - 按下游决策关注点分组章节

**理由：**将正文重排为安全与内容边界、架构与数据决策、模型/证据机制，使读者先看到风险约束，再看到实现细节，并可按职责快速扫描。
**影响：**约 0 个英文单词。
**理解说明：**不删除内容即可改善人类阅读路径；建议顺序为伤病筛查、动作反馈边界、动作教学素材、平台路线、持久化/数据放置、体积预算、RPE，最后是忘记结束信号。

### 2. MOVE - 将已接受的 Apple 路线放在被否决的 vivo 路线之前

**理由：**Pyramid 结构要求当前决策和状态先于历史上的被否决方案理由。
**影响：**约 0 个英文单词。
**理解说明：**完整保留 vivo 理由，同时让当前生效的平台路线立即可见。

### 3. QUESTION - 将素材授权与动作反馈可行性拆分

**理由：**`内容与动作反馈边界` 混合了受法律约束的内容来源与传感器能力限制，拆成两个 H2 章节可使结构更符合 MECE，也更便于分别路由给合规读者与架构/UX 读者。
**影响：**约 0 个英文单词。
**理解说明：**这会新增一个主要标题，但保留每一段并改善随机访问；应用前应由作者确认两个章节的边界。

### 4. CONDENSE - 伤病筛查与康复边界

**理由：**保留提议行为、官方来源理由、已确认的非诊断边界及 `FR-058`/`NFR-SAFE-001` 引用，同时将末段重复的操作行为压缩为更短结论，因为 `prd.md` 是权威来源。

## 总结

- **建议总数：**8。
- **预计缩减：**若全部接受，约减少 150 个英文单词（原文的 10.4%）；中文版应保持含义等价，不应机械匹配字符数。
- **是否满足长度目标：**未指定目标。
- **理解权衡：**建议中的删减不会牺牲证据来源、安全边界、被否决方案理由或下游机制；唯一直接删除项只是合并重复的数据放置规则。
- **总体结论：**addendum 内容可靠且范围正确，但按关注点重排、拆分一个章节并定向压缩，将改善 Pyramid 信息流，并强化 `prd.md` 作为唯一规范性来源的地位。
