## Gate 结论

补充材料内容总体可靠，且中英文版本保持同步。现有内容大多正确承担了下游论证、证据、淘汰方案历史或技术机制的职责。正式定稿前应先解决四项边界与覆盖缺口：将一项安全发布约束提升进 PRD；在保留 PRD 产品级约束的同时，把云端数据架构理由记录进补充材料；将技术特定的模型与体积验证细节移出规范性产品契约；防止重复规则演变成相互竞争的事实来源。

## 对账缺口

### GAP-ADD-001 — 伤病警示升级与专业审核尚未成为 PRD 规范要求

**严重性：**对 Post-MVP 新手计划发布为高；UJ-4 维持延期时，不阻塞 MVP 上线。

补充材料记录了两项 FR-058 未完整覆盖的已确认产品约束：命中警示症状时停止生成计划，并引导用户线下就医且不命名诊断；筛查问题和升级提示文案在上线前必须经过专业审核。这些是用户可见的安全行为和发布 Gate，并非只有监管论证价值。

**建议解决方式：**新增一条 Post-MVP 功能需求或安全 NFR，同时保留以上两项约束。监管分析、被否决的康复路线和来源链接继续留在补充材料。不要把详细法律解释提升进 PRD。

### GAP-ADD-002 — 已接受的云端数据决策缺少补充材料架构记录，PRD 的治理约束也不完整

**严重性：**对架构交接为高。

memlog 区分了 FitnessAI 应用云同步与 Apple iCloud/CloudKit，并记录个人健康信息不得存储在 iCloud/CloudKit；因此需要独立设计符合中国区要求的应用后端，同时完整高频传感器流保留在本地。PRD 已覆盖本地优先写入、中国区同步、恢复和传感器流本地保留，但没有陈述已接受的 iCloud/CloudKit 禁用边界。补充材料也完全没有专门的持久化/同步理由章节。

**建议解决方式：**在 PRD 中新增产品级数据治理 NFR，说明 iCloud/CloudKit 存储禁用边界；跨设备结果、离线行为、中国区合规、冲突安全、导出和删除继续留在 PRD。补充材料新增章节，记录被否决的 iCloud/CloudKit 路线、本地优先/应用后端机制、同步数据类别、压缩模型摘要兼容性以及高频数据流本地性。不要把特定后端供应商写进 PRD。

### GAP-ADD-003 — PRD 对技术特定的模型与发布体积机制规定过细

**严重性：**中。

PRD 合理需要可测的体积上限、不确定性行为、发布证据和用户负担 Gate。但是，`Core ML` 产物分配、逐模型打包目标、8–10 MB 架构评审触发点、轻量校准在本地/iPhone 的执行位置、内容服务放置方式，以及 Xcode/App Store Connect/TestFlight 测量机制，都描述了解决方案和验证实现。补充材料已经包含部分 RPE 部署机制，却没有体积预算理由或发布测量方法。

**建议解决方式：**平台硬限制、用户认可的安装体积上限、Watch 预留空间目标、发布证据要求和产品可见的 RPE 信任行为继续作为 NFR。把技术特定的分配、计算位置、打包策略、测量工具和架构评审理由迁移或镜像到补充材料；简化 FR-023/NFR-RPE-008，只要求使用纠正标签重新校准，不规定执行位置。编辑 PRD 时保留稳定 ID。

### GAP-ADD-004 — 补充材料重复规范性产品规则，却没有声明 PRD 为权威来源

**严重性：**中等漂移风险。

补充材料使用规范性措辞重述了精确的 RPE 验证阈值、自动采用规则、伤病行为、媒体禁令和忘记结束 AND Gate。它们目前与 PRD 一致，但未来编辑可能形成两份相互竞争的需求契约。补充材料的正确职责是证据、理由、备选方案和机制。

**建议解决方式：**增加简短范围说明，声明 PRD 是产品行为与验收要求的权威来源。在重复章节中保留理由和技术细节，再通过稳定 FR/NFR ID 引用规范行为。只有用于记录下游实施尽调的补充材料特有禁令继续保留，例如直接取得 Gym visual 许可证的条件。

## 必须留在 PRD 的未决项

`SM-RET-001` 和 memlog 仍未确定试点人群的验收阈值。这是产品成功决策，不属于补充材料。必须在试点留出集评估前解决，或明确延期负责人和复查条件；将其移入补充材料会隐藏产品 Gate。

## 双语一致性

**状态：通过。**

- `addendum.md` 与 `addendum.zh-CN.md` 均为 49 行，标题层级相同，包含同样的五个内容集群，段落结构一致。
- 三个来源链接、行内路径、仓库名称、字段标识和研究报告路径在两个版本中全部保留。
- 中英文版本表达了相同的平台选择、许可证禁令、腕部传感限制、伤病边界、RPE 信任规则和忘记结束行为。未发现实质翻译偏差。
- `prd.md` 与 `prd.zh-CN.md` 均为 262 行，并保留相同的 FR-001–FR-060、NFR、SM 和 UJ 标识。PRD 双语对中未发现与补充材料相关的不一致。

## Memlog 覆盖结论

补充材料正确保留了平台选择、教学素材、动作传感、伤病范围、RPE 估算和忘记结束提醒等主要淘汰方案与下游技术深度。实质遗漏是已接受的云端数据架构理由；需要提升进 PRD 的实质缺口是伤病警示/专业审核发布约束。其余问题属于放置边界：应把技术特定的 RPE 和体积验证机制集中到补充材料，使 PRD 继续作为稳定的产品契约。
