# FitnessAI AI-MVP Fast-Path 评审

**日期：**2026-09-08  
**评审范围：**AI-native MVP 与首个可用版本 / 私有 Alpha 切分新增或暴露的 critical/high 问题。  
**已审产物：**`prd.md`、`prd.zh-CN.md`、`addendum.md` 与 `addendum.zh-CN.md`。  
**结论：需要修改——无 critical 发现；五项 high 发现。**

本次更新已经建立预期的 AI-native 闭环，并保持稳定 ID 和双语结构一致。但还不能直接作为 fast path 交给 Architecture/Epics：私有 Alpha 的适用范围仍不是规范合同；Watch 传递与原子性措辞冲突；批准流程仍可能隐藏非“重要”变化；AI 数据权限定义不足；安全 Gate 对已披露伤病的保护比普通 AI 生成计划的安全保护更完整。

## High 发现

### H1 — 私有 Alpha 切片没有规范性的 FR/NFR 适用合同

**位置：**`prd.zh-CN.md:176-205`，重点为 §6.1 与 §6.3；§7–§8 中所有未限定适用版本的需求。英文对应：`prd.md:176-205`。

§6 表示自动识别、自动 RPE、智能结束提醒、应用云端账号、完整分析和丰富教学媒体不阻塞首个可用版本。但这些能力的 FR 和 NFR 仍作为一份名为“MVP 范围”的文档中的无条件需求存在。下游 Architecture 或 Epic 生成器完全可能把 FR-005、FR-008–015、FR-020–027、FR-036–048、FR-051–053、FR-067–070，以及识别/RPE/会话 Gate 与 public cloud 约束，都当作第一版验收的必需项。这会让 fast path 虽然在范围文字中成立，却仍在需求层失效。

**必须解决：**增加一份规范性的版本适用表，或明确列出首个可用版本需求 ID 集与后续 Public-Beta 需求 ID 集。Alpha 集至少覆盖手动计划训练路径、本地持久化/恢复、规范动作映射、FR-054–060、FR-078–085、适用的本地运行/安全需求，以及最低安全和隐私条款。明确声明：集合外需求继续作为 Public-Beta 承诺有效，但不阻塞 Alpha 的 Architecture、Stories 或验收。不得重编号现有 ID。

### H2 — Watch 传递同时被描述为可观察的最终一致过程和本地激活的一部分原子事务

**位置：**`prd.zh-CN.md:132`、`prd.zh-CN.md:162`、`prd.zh-CN.md:184-186`、FR-081–084（`prd.zh-CN.md:331-335`）以及 NFR-AI-003（`prd.zh-CN.md:407`）。英文对应：`prd.md:132`、`162`、`184-186`、`331-335`、`407`。

FR-081 明确允许计划修订生效后 Watch 传递仍处于待发送或失败；NFR-AI-003 却称“计划提交与传递重试必须具备原子性”，并只允许完整旧修订或完整新修订成为生效状态。在现有离线模型中，跨设备传递无法与 iPhone 本地提交组成原子事务。因此当前文本无法决定传递待定或失败时，Watch 可以展示或执行哪个修订。

**必须解决：**把原子性限定为 iPhone 本地计划修订的创建/激活。Watch 传递定义为幂等和最终一致。传递待定或失败时，Watch 可以继续展示最后一个成功送达的兼容修订，但必须清楚标明修订/状态，绝不能声称新修订已可用。训练会话在 Start 时快照 Watch 上的修订，并在本次会话中保持该快照。NFR-AI-003 不得把远程传递成功纳入本地原子事务。

### H3 — “重要 Diff”给未展示的生效变化留下批准漏洞

**位置：**UJ-4 第 6 步（`prd.zh-CN.md:107`）、AI 计划提交 Gate（`prd.zh-CN.md:140`）、用户批准定义（`prd.zh-CN.md:163`）、FR-057（`prd.zh-CN.md:296`）与 FR-060（`prd.zh-CN.md:299`）。英文对应：`prd.md:107`、`140`、`163`、`296`、`299`。

PRD 多次要求展示“重要”字段级 Diff，却没有定义何为重要。实现可以把某个变化归类为非重要、从审核中省略，然后仍以包含该隐藏变化的修订获取批准。这与 SM-AI-002 和用户确认的禁止静默改写决定冲突。

**必须解决：**批准载荷必须包含每一项会生效的新增、删除和修改。“重要”只能控制视觉强调或摘要顺序，不能控制是否展示。批准必须绑定不可变的 proposal/revision ID 或内容摘要；展示之后发生任何重新生成或内容变化，既有批准立即失效，必须重新审核。

### H4 — 敏感 AI 输入权限不足以明确授权远程处理

**位置：**iPhone 数据范围同意（`prd.zh-CN.md:130`）、首个可用版本输入（`prd.zh-CN.md:182`）、FR-054 与 FR-059（`prd.zh-CN.md:293-298`）、FR-078 与 FR-082（`prd.zh-CN.md:329-333`）、NFR-PRIV-007（`prd.zh-CN.md:394`）以及补充材料 AI 边界（`addendum.zh-CN.md:49-55`）。英文对应为各英文文件相同行号。

FR-082 要求结构化记录“获得明确许可”，但 PRD 没有定义何时请求许可、许可按提案还是持续有效、包含哪些记录/时间范围、如何撤回，以及撤回后已生成草案如何处理。NFR-PRIV-007 要求远程 AI 传输前披露，但没有要求与披露数据类别绑定的肯定操作。身体限制、伤病、主观反馈与训练历史即使在 Product Owner Alpha 中也可能属于敏感输入。

**必须解决：**在任何远程请求前定义最小权限状态：用户看到并肯定批准所含数据类别与记录/时间范围；提案保留该范围；撤回后不得继续使用，并使失去授权依据的草案失效或明显标记。明确区分本地处理与远程传输。provider、保留、模型训练用途和跨境处理可以在 Alpha 中继续作为实现/配置选择，但必须在传输前披露，且不得从一般 App 同意中推定。

### H5 — 安全 Gate 保护已披露伤病场景，但未覆盖普通 AI 生成计划内容

**位置：**FR-058（`prd.zh-CN.md:297`）、NFR-SAFE-001（`prd.zh-CN.md:401`）与 NFR-AI-006（`prd.zh-CN.md:410`）；补充材料安全边界（`addendum.zh-CN.md:27-33`）。英文对应：`prd.md:297`、`401`、`410`；`addendum.md:27-33`。

当用户披露伤病、恢复状态或警示征兆时，规范安全行为已经较强；但对于其他普通 AI 生成计划，仍没有最低校验合同，例如互相矛盾的日程/训练量、不支持的重量单位、不可能或缺失的组次处方、过度渐进，或超出受支持健身范围的建议。NFR-AI-006 使用“超出安全边界”一词，却没有定义排除合同。因此结构有效的计划仍可能在内容上不安全或荒谬。

**必须解决：**增加版本化的最低计划安全校验合同，并在私有 Alpha 中也于提交前执行：支持的单位/范围、适用时必要的休息/恢复字段、矛盾检测、不支持处方拒绝，以及非医疗范围边界。Product Owner-only Alpha 可以使用明确标记的测试规则包，不必等待完整专业签字；任何超出 Product Owner 测试的发布，仍须由专业人员对伤病流程和计划安全规则/内容包共同完成文档化审核。
