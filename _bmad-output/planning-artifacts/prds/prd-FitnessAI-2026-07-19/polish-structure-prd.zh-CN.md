## 文档摘要

- **目的：** 面向产品、UX、架构和 Epic 读者的链路顶层发布 PRD。
- **受众：** 决策者和下游产品开发工作流。
- **读者类型：** 人类；保留能实质提升理解的定位信息、具名旅程、示例、边界情况和便于扫描的辅助元素。
- **核心问题：** FitnessAI MVP 必须交付并证明什么，才能作为一个可信、近乎零交互的力量训练记录工具发布？
- **本文档旨在帮助：** 产品、UX、架构和 Epic 决策者就 FitnessAI MVP 范围、用户权威不变量、需求和发布 Gate 达成一致。
- **结构模型：** 战略/上下文（金字塔）。
- **已应用的风格指南：** 保持中英文结构一致，保留稳定的需求与决策 ID、表格、代码、链接和结论；以分组功能及其嵌套 FR 组织正文，将跨领域 NFR 单列；未在 PRD 中赢得位置的实现细节放入 addendum。
- **当前长度：** 英文版共 7,178 词，包含 9 个编号主章节和 24 个子章节（共 33 个章节）。同步中文源文档具有相同的 349 行结构；其 1,382 个空白分隔 token 无法与英文词数直接比较。

## 建议

### 1. MOVE - 将关键用户旅程移到面向决策的范围与 Gate 摘要之后

**理由：** 决策者目前需要先阅读 1,572 词的旅程，才能看到支持设备边界、MVP 范围和证据 Gate；应将目标用户和待完成任务保留在前部，再把旅程放到范围之后，让叙事去演示一个已经定义好的产品。

**影响：** 约 0 词。

**理解说明：** 保留所有具名主角、进入状态、高潮、结局和各不相同的边界情况；这里只改变顺序，不改变含义。

### 2. MOVE - 将发布决策与 Gate 集中到文档前部

**理由：** 紧接成功指标创建一个面向决策的“MVP 发布决策与 Gate”章节，集中现有 §3.2 Gate 摘要、嵌在 §2.2 中的程序性 Gate 条款以及 §9 的 Owner/重访条件，同时保留每个 SM/DV ID，并让每个详细验收阈值只出现一次。

**影响：** 通过删除重复的预注册、holdout 和重访表述，约减少 160 词。

**理解说明：** 这会前置发布状态和证据义务，而不会削弱任何 Gate。

### 3. CONDENSE - 关键用户旅程

**理由：** 保留每个 UJ ID 及其人物/上下文、进入状态、关键决策路径、高潮、结局和独有边界情况，但删除对后续详细 FR/NFR 策略的复述，尤其是 RPE 验证、纠错数据保留、计划更新权威和同步行为。

**影响：** 约 700 词。

**理解说明：** 不要把旅程缩减为纯需求引用；具名叙事是高价值的人类理解辅助元素。

### 4. MOVE - 将所有 Post-MVP 新手计划内容集中到末尾章节

**理由：** 将 UJ-4、FR-054 至 FR-060、NFR-SAFE-001 和 DV-003 移到所有 MVP 需求之后的单一“Post-MVP 新手计划”章节，使未来阶段内容不再打断 MVP 阅读路径。

**影响：** 约 0 词。

**理解说明：** 完整保留伤病安全 Gate 和显式批准行为；本建议只改变阶段分组。

### 5. MERGE - 围绕两个端到端生命周期重组功能需求

**理由：** 将 §7.1 与 §7.9 合并为“训练会话记录、纠错与恢复”，并将 §7.6 与 §7.10 合并为“账号、离线使用与同步生命周期”，按照从开始到恢复/删除的顺序排列需求，同时保留每个 FR ID 和表述。

**影响：** 约 0 词。

**理解说明：** 生命周期分组能减少随机跳读，同时不改变下游需求引用。

### 6. CONDENSE - 将 RPE 能力规则与可测量可靠性 Gate 分离

**理由：** 在 FR-020 至 FR-026 中保留面向用户的启用、五次估计验证、同意、纠错和来源行为，在 §8.2 中保留评估、不确定性、漂移、负担和 holdout 验收；缩短 NFR-RPE-007 至 NFR-RPE-010 中重复功能策略的部分，同时保留所有 NFR ID 和结论。

**影响：** 约 130 词。

**理解说明：** 保留整数刻度、资格分母、漂移触发器、冻结 Gate 记录和每一个可测量阈值。

### 7. CONDENSE - 将 MVP 范围压缩为定位层

**理由：** 保留五组范围内能力，但缩短已在 FR/NFR 中表达的逐句策略和验收细节，使 §6 回答“什么属于 MVP”，而不是部分重复“如何验收”。

**影响：** 约 85 词。

**理解说明：** 精简后的范围仍是有用的扫描辅助，不应删除。

### 8. MERGE - 合并非目标与 MVP 范围外

**理由：** 将 §6.2 中唯一的新手计划排除项移入 §5，并删除随之变空的子章节，因为同一 Post-MVP 边界已在该处陈述。

**影响：** 约 15 词。

**理解说明：** 保留明确的 Post-MVP 标签和 UJ-4 引用。

### 9. PRESERVE - 人类理解与验收锚点

**理由：** 保留术语表、反向指标、具名旅程人物、各不相同的边界情况、支持矩阵语言和数值证据阈值，因为它们能防止决策者与下游工作流产生歧义解释。

**影响：** 约 0 词。

**理解说明：** 删除这些元素对可扫描性、可测试性或共同理解造成的损害，会大于其带来的精简收益。
