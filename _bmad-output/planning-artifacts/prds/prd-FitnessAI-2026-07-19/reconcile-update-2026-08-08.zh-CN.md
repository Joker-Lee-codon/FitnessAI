## 跨输入一致性

### 产品简报

未发现冲突。产品简报的核心承诺仍是近乎零交互、可信记录、可逆自动化与用户权威。简报要求在记录完整性得到验证前排除大范围 AI 教练；更新后的 PRD 强化了这一点，并未与之矛盾。简报中的通用账号级导出与新规划的 V1.1 单计划往返文件保持区分：前者由 PRD NFR-PRIV-005 约束，后者由 FR-071 至 FR-073 约束。

### 现有 UX EXPERIENCE 与 DESIGN

现有 UX 与 MVP 边界及新增护栏保持一致：

- Apple Watch 继续是训练中权威界面，本地可靠提交继续是“已保存”边界。
- 建议的动作替代、下一组重量、计划差异与未来渐进调整均需要用户明确操作。
- 来源、pending/冲突状态、纠错、可审计性以及本地与云端事实边界，已经是核心 UX 原则。
- `DESIGN.md` 将 action 样式保留给用户权威操作，并明确避免把视觉状态表示成“AI 已批准”。

UX 文档目前没有把语音、可移植单计划文件、第三方格式或二维码/链接分享宣称为 MVP 能力，因此不存在范围矛盾。

## 真实缺口

### UX-01——现有 UX 需求追踪止于 FR-070

- **严重程度：**中等下游对齐事项；不是 PRD 阻断项。
- **证据：**`EXPERIENCE.md` 的 Requirements-to-Flow Coverage 表以 FR-067–FR-070 结束，没有覆盖 FR-071–FR-077，也没有覆盖 NFR-PORT-001、NFR-VOICE-001 与 NFR-SHARE-001 的流程或状态。
- **为何这是真实缺口：**PRD 现在包含 UX 文档 Finalize 时尚不存在的规划能力与架构保留约束。如果没有明确的 UX 增量，未来团队可能把 V1.1 计划可移植性误解为普通账号导出，或在设计语音/分享流程时遗漏草稿、来源、预览、冲突、权限与数据最小化状态。
- **要求的跟进：**以阶段化附录或修订方式更新 UX。定义 V1.1 单计划导出/导入旅程及其不可信文件、预览、映射、部分失败、重复、取消和新草稿状态。对 Post-MVP，仅记录用户主动唤起语音与二维码/链接分享的非实现性状态契约；不得把它们加入 MVP IA 或视觉实现范围。

## 双语一致性检查

本次更新的英文与中文 PRD 副本具有一致的行数、章节顺序、稳定需求编号、阶段标签与结论。附录副本同样保持章节顺序一致，并保留相同的范围、隐私、来源与禁止覆盖约束。此次审阅未发现更新内容存在双语语义分歧。

## 最终核对结论

本次 reconciliation 不要求修改 PRD。更新后的 PRD/附录可以继续通过剩余 Finalize Gate。唯一跟进项是：让现有 UX 文档与 FR-071–FR-077 对齐，同时把全部新流程保持在 MVP 之外，并维护 PRD 规定的阶段实现边界。
